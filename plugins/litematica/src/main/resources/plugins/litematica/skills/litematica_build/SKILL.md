# Skill: litematica_build

主人可以在 Litematica 里把一张图纸"放"到世界上——那个半透明的影子就是他脑子里的房子。
`litematica` 工具直接读<b>他屏幕上那一份</b>:图纸是哪个、放在哪一格、转过多少、要不要镜像。
所以这件事<b>不需要他再报一遍坐标</b>,也不该由你猜。

## 先取回工具定义

`litematica` 是渐进披露的工具:先 `find_tools(["litematica"])` 把参数拿回来再调。
直接调会被挡下——引擎按"你眼前有没有这份定义"判,不是按你记不记得住判。

## 三步

1. `action=list` —— 现在加载了哪几张。多张时用名字或序号挑;主人没指名,就用
   `action=info`(不填 placement,即"他现在选中的那张")问一句再动手。
2. `action=check` —— <b>只看不动</b>:这张投影已经立了多少、还差多少料、她手上缺什么。
   生存模式下报价单就是这一步的全部价值:先说清楚要多少,再一起去采,最后才施工。
3. `action=build` —— 照投影原位整幢施工。它等同 `blueprint action=build`:
   生存每格消耗一件,大工程一趟运不完是常态,备好料再用<b>同一张投影</b>调一次即可续建。

做完再 `action=check` 看一眼,把"还差什么"告诉主人,而不是只回一句"建好了"。

## 锚点、旋转、镜像都是投影自己的

工具会把这三样算好——锚点是变换后整幢东西的最小角,旋转是顺时针角度,镜像是先镜像后旋转。
<b>不要自己改,也不要拿投影的原点当锚点</b>:原点是主人点下去的那一格,旋转或镜像之后
它通常不是最小角。改了,房子整体偏出去,而且每一格都"成功"——最难查的那种错。

镜像也别自己推:`left_right` 翻的是 Z 轴,`front_back` 翻的是 X 轴。猜反了,
两种摆法的格子数一模一样,只有带朝向的方块全反。

## 做不了的要直说

- 投影在 Litematica 里是<b>关着</b>的(工具会标 `enabled_in_litematica: false`):
  屏幕上什么都没有,你却在盖楼。先跟主人说一声,别默默开工。
- `buildable: false` 的投影(区域尺寸为负,或子区域被单独转过/镜像过)整张图<b>不是</b>
  "一个旋转加一个镜像"能表达的。工具会给出原因,照实转述,别硬盖。
- 图纸不在服务端 `schematics/` 目录时会报找不到。工具会附上文件在主人客户端上的路径,
  那就是他要复制过去的那个文件——把路径原样告诉他。

## 别做的事

- 主人没提投影时,不要自己翻出投影来盖:投影是他摆的,不是你的施工单。
- 别为了"让坐标对上"而去改他的投影——那是他的界面,动了就是动他的东西。
- 同一张投影反复建、反复失败时停下来:先 `action=check` 看差在哪,
  再判断是缺料、位置被占,还是这张图本来就做不了。
